# 术语表

这个仓库里反复出现的词，按"说人话"的方式解释一遍。左边是日常说法，中间是代码/文件里的标识。

## 音效系统

| 术语 | 代码 / 文件里的标识 | 含义 |
|---|---|---|
| 音效 | — | 敲键盘时放出来的那一下声音 |
| 音效包 / 音效 | `scheme`、`AudioScheme` | 一整套音效，比如"打字机"。一个音效包 = 一个目录 + `schemes.json` 里一条记录 |
| 音效目录名 | `AudioScheme.name` | 目录名，**必须纯 ASCII**。它会被直接拼进文件路径，而 `load_scheme()` 里的 `chars().count()` / `truncate()` 单位不一致，含中文会 panic |
| 显示名 | `AudioScheme.display_name` | 下拉框里显示的名字。它同时是本地化查找的 **key**，不是普通字符串 |
| 采样 | `files` 里的 `.wav` | 一段"敲了一下键"的录音。敲键时从这组文件里随机挑一个放 |
| 重复度 | `AudioScheme.non_unique_count` | 前 N 个文件是"通用键音"，按 `键码 % N` 取。N 越大，同一个声音重复越少 |
| 按键映射 | `AudioScheme.key_audio_map` | 特殊键 → `files` 下标的映射。普通键走 `non_unique_count`，不在这里 |
| 键码 | `keycode` | macOS 的虚拟键码。`36` = 回车，`49` = 空格，`51` = 退格，`48` = Tab |
| VK 码 | Windows 虚拟键码 | Mechvibes 素材的文件名用的是这个：`13` = 回车，`32` = 空格，`8` = 退格 |
| 音量 | `volume`、`pref.volume` | 界面上第一根滑动条，对所有音效一起生效 |
| 音调 | `pitch`、`pref.pitch` | 界面上第二根滑动条。1.1.0 版还有"自动音调"（打字越快音调越高） |
| 静音 | `mute` | 当前前台 app 命中黑/白名单时静音 |
| 白名单 / 黑名单 | `FilterList`、`FilterListMode` | 决定哪些 app 上放音效、哪些不放 |

## 轴（机械键盘开关）

| 术语 | 含义 |
|---|---|
| 轴 | 机械键盘的单个按键开关。"青轴""红轴"说的就是它 |
| 线性轴 | 直上直下、没有段落。红轴、黑轴、NK Cream 都是 |
| 段落轴 | 中途有一个"顶一下"的手感。茶轴是典型 |
| 咔哒轴 | 段落 + 故意做响的咔哒声。**青轴**是典型，也就是"打游戏那种特别吵的" |
| 静电容 | 不用金属触点、靠电容变化触发。Topre 是代表，声音是闷响（"thock"） |
| 办公向 | 本项目里的定义：**不刺耳**，不是"音量小"。见下面"尖刺" |

> **轴的名字不等于声音。** 同一型号的轴，不同录音可以从很闷到很尖。
> 判断听感只能基于实际那几个文件，不能基于型号名。

## 音频度量

这次选轴用的三个指标：

| 术语 | 怎么算 | 含义 |
|---|---|---|
| 绝对响度 | 全频段 RMS，单位 dBFS | 整体多大声。**音量条能改的就是这个** |
| 尖刺（绝对） | 4kHz 以上能量，单位 dBFS | 有多少高频。高频多 = 扎耳 |
| **同音量下的尖刺** | 尖刺（绝对） − 绝对响度 | **把音量条调到一样大之后谁更尖。越低越闷** —— 这才是选办公向轴的关键指标 |

其它：

| 术语 | 含义 |
|---|---|
| 削波 | 波形超过满刻度被削平，会听到"破音"。所以每个文件峰值都留余量 |
| 峰值余量 | 峰值离满刻度还差多少。本项目每个文件留 0.5dB |
| 首尾静音 | 录音开头/结尾的空白。不掐掉会导致按键响应迟、且各包 RMS 没法公平比较 |
| 静音坏样本 | 内容全空、但文件名正常的采样。`topre` 的 B 键就是，已剔除 |
| 单声道 / 44100Hz / 16 位 PCM | 本项目所有音效的统一格式。单声道 44.1k 16bit 是最保险的 |

## 本地化与文件

| 术语 | 代码 / 文件 | 含义 |
|---|---|---|
| 本地化查找 | `l10n_str()` | 拿显示名去 `Localizable.strings` 里查翻译。**找不到键返回空串**（`value:@""`），所以下拉框会出现空白行 |
| l10n 键 | `Localizable.strings` 左边的字符串 | 本项目里就是 `display_name` 的原值。加音效必须同时加键，否则显示为空白 |
| `Base.lproj` | `Tickeys.app/Contents/Resources/Base.lproj/` | 开发语言的字符串表，**UTF-8** |
| `zh-Hans.lproj` | `Tickeys.app/Contents/Resources/zh-Hans.lproj/` | 简体中文表，**UTF-16LE 带 BOM**（改的时候必须按原编码写回） |
| `schemes.json` | `data/schemes.json` | 音效清单。Rust 版和 C# 版 1.1.0 读的是同一套格式 |

## 这个仓库的特殊情况

| 术语 | 含义 |
|---|---|
| Rust 版 | 本仓库，0.5.0，2015~2020 年的代码。**在 Rust 1.89 下编译不过** |
| C# 版 / 1.1.0 | 用户实际在跑的 `/Applications/Tickeys.app`，Xamarin.Mac + Mono，2020-12-03 构建，闭源、本机无源码 |
| 数据改动 | 加音效目录、改 `schemes.json`、改 `Localizable.strings`、改 `changelog.md`。**改动小、两个版本通吃** |
| 代码改动 | 碰 `src/*.rs`。本次完全没碰 |
| `alut` | 用来解码 wav 的老库（OpenAL Utility Toolkit）。对 wav 里的额外 chunk 挑食，所以生成的 wav 只保留 `fmt` + `data` |
| `get_res_path()` | 把相对路径拼成 `Tickeys.app/Contents/Resources/` 下的绝对路径 |
